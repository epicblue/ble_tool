# 蓝牙 BLE 助手 · 附体能训练模块

一个基于 Android（Java）的 BLE 调试小工具（扫描/连接/读写特征值），
并在其上新增了**摄像头人体姿态捕捉**的体能训练模块。

## 主要功能

### BLE 调试（原有）
- 扫描周边 BLE 设备、查看信号强度
- 连接设备、查看服务与特征值、收发数据
- 长按「扫描设备」进入调试页

### 体能训练（新增）
用摄像头实时识别 33 个人体关键点，自动统计并回放以下动作：

- 🤸 **倒立**——坚持时间 + 稳定度
- 🧗 **靠墙倒立**——坚持时间 + 贴墙代理估计 + 稳定度（不能确认接触墙面）
- 🪑 **折凳俯卧撑**——双手撑凳（上斜）/ 双脚垫凳（下斜）
- 💪 **俯卧撑**——有效次数
- ⚠️ **不标准俯卧撑**——不标准次数与原因（幅度不足 / 塌腰撅臀 / 跪姿）
- 🧘 **平板支撑**——坚持时间，塌腰时暂停计时并提醒
- 🏋 **深蹲**——次数（只抖膝不下蹲不计数）
- 🧲 **引体向上**——次数（只弯手臂没上去不计数）
- 🧱 **靠墙蹲**——多组有效时间实时累计，并显示本组、最长单组和稳定度（姿势不合格时暂停计时）
- 🏃 **跑步计步**——步数与步频（以左右脚踝交替为信号，尽量过滤轻微晃动）

动作判定使用抗抖动滤波和尺度归一化；实时骨架显示模型原始点。不同机位、光照和设备下仍需实测。
共 10 个动作：倒立、靠墙倒立、折凳俯卧撑、
俯卧撑、不标准俯卧撑、平板支撑、深蹲、引体向上、靠墙蹲、跑步计步。

同时支持：
- **回放**：有视频时默认从原 MP4 重新识别骨架；无视频时仍可回放录制骨架。支持进度拖动与 0.5x~2x 倍速（视频倍速需 Android 6.0 及以上）；设备上的时空对齐仍需验证
- **视频导出**：在回放页点「导出视频」，通过系统文件选择器保存原始 MP4；不含回放时叠加的骨架、标记和成绩
- **成长星球 / 历史记录**：星星与徽章鼓励每次尝试，保留按动作筛选、缩略图、成绩、回放和删除
- **账号切换**：多人共用一台手机时，训练数据彼此隔离
- **个人校准**：俯卧撑（含折凳/不标准）、深蹲、引体向上可将当前最佳幅度设为个人目标，点击即记一次；按账号和动作保存、可重置

### 骨骼标记与场景提示

1. 进入动作的训练页后，即使尚未开始计数也可以先看标记、调整机位；说明挡住画面时点「收起说明」。
2. 「标记：开/关」控制详细标记，关闭后基本骨架仍显示：绿点为置信度 ≥50%，黄点为 30–49%，
   旁边显示关键点名称和估计置信度；紫圈表示该点的新位置尚未被滤波器采纳，旧位置可能短暂保留。没有点可能是遮挡、出画或置信度过低。
3. 画面顶部会提示关键点缺失、出画、过小、靠近边缘等。置信度是模型对关键点入画的估计，**不是识别准确率**；
   多人同框时没有身份追踪，建议仅一人入镜。长时间无新帧时旧骨架会被清除；帧间隔过大时也会提示卡顿。
4. 打开带视频的历史记录后，App 会先在后台从原 MP4 抽帧，用当前模型重新识别；完成后默认播放「新滤波」骨架。
   等待时可点「取消识别」返回普通回放，失败或取消后可重试。点「骨架：新原始/新滤波/录制」循环对照：
   新原始显示模型点及滤波待定紫圈；新滤波显示当前滤波结果；录制模式显示当时保存的滤波骨架。
   没有视频时继续使用纯骨架动画。录像方向、前摄镜像及时间对齐仍需真机验证。

训练判定会屏蔽画面外的关键点，对持续的大跳变等待稳定后重新捕获，并优先使用同侧可信躯干；
倒立需看到抬起的脚踝，靠墙蹲可在一侧膝点被遮挡时使用可信侧。长时间丢帧或关键关节缺失时不会把空白当作已观察到的动作。详见 [功能说明](docs/fitness-module.md)。

**深蹲镜头横移**：进入深蹲时可选「逐帧重新找人」（建议，可能较慢）或「连续跟踪」（较快，横移时可能跟错）。
逐帧模式每张图重新检测人物，不能保证模型一定恢复；若顶部持续提示识别偏慢，退出训练回到列表可选择连续跟踪，
并尽量固定手机。判定用滤波器还会在可信肩、髋、踝持续一致横移后尝试恢复；恢复条件、防误计及录像效果均需真机验证。

### 用录像验证当前骨架算法

- 新识别默认每 `100ms` 取一帧，长录像自动降低采样密度，超过 35 分钟暂不支持重识别；处理可能较慢，离开页面会取消。深蹲使用逐帧重新找人，其他动作使用连续跟踪。新骨架和重算成绩只在本次回放内存中，不覆盖录像、录制骨架、历史成绩或个人设置。
- 视频帧按请求时间附近解码，拖动/倍速按视频时间查看，但不是逐视频帧精确同步；快速动作可能漏掉。新识别只使用训练开始时的个人目标，**不重放组内校准点击，也没有当时可对齐的重力补偿**，因此重算计数仅供对比；界面另列历史保存成绩。录制骨架模式仍保留原校准事件。
- 重点验证深蹲横移：等待识别完成，在站直前后拖动进度条，分别看「新原始」是否还折叠、「新滤波」能否恢复，再与「录制」对照。新识别不保证模型一定恢复或选中同一人。

### 成长星球：给每一次尝试一点鼓励

- 在动作列表点「成长星球 · 历史记录」，或训练完成后点「成长星球」。页面按当前账号的记录（训练完成入口则使用本次训练所属账号）展示运动足迹数、记录天数、动作种类和最近 7 天的星星；点「看足迹」可直接跳到记录，顶部仍可按动作筛选。
- 「星球启航」「花样探索」「闪亮足迹」分别根据 **1 条记录、3 种动作、5 个不同日期**生成；点徽章可以查看说明。没有连续打卡或限时要求，不同账号各自计算，休息也很重要。
- 统计和徽章使用所显示账号的**全部已保存记录**，不受筛选影响；删除记录后会按剩余数据重新计算。日期按设备当前时区划分，未知或未来时间不计入天数；没有点亮只表示 App 没有当天的记录，不代表没有活动。徽章不评判动作是否标准或安全。

### 靠墙蹲累计和视频导出

- 靠墙蹲的大号数字为**本次训练各组有效时间之和**；下方另有本组和最长单组。短暂姿势不合格时暂停累计，
  达到起算条件后累计会继续增长；结束后同时保存累计与最长单组。旧记录未保存累计时不会把最长单组误当累计。
- 打开一条带视频的历史记录 → 回放页「导出视频」→ 选择保存位置，等待完成提示。
  导出的是原始 MP4，**没有骨架、关键点标记或成绩叠加**；只有骨架的记录不能导出视频。
  原记录不受影响，删除训练记录也不会删除已导出的副本。若导出失败或中途退出，请检查保存位置是否有不完整文件。
- 使用系统文件选择器不需要申请额外存储权限；若选择云盘，文件提供方可能会上传所选副本。导出和播放器效果仍需真机验证。

### 个人校准怎么用

开始支持校准的动作后，先回到起始位，再保持在当前能够做到的最好位置，点击「**个人校准 +1**」
（可请同伴帮忙点击；独自训练可长按按钮，5 秒后采样，倒计时内点按可取消）。确认后立即记一次，并保存当前账号、该动作及折凳变体的目标；
回到起始位才能开始下一次。以后达到个人目标即可计数；在「账号 → 个人校准设置」可查看或恢复默认。
校准并不意味着动作标准或安全，原有姿势提醒仍会显示。计时类和跑步计步暂不支持此按钮。

## 构建

```bash
# Windows
gradlew.bat :app:testDebugUnitTest    # 动作判定单元测试（纯 JVM，无需手机）
gradlew.bat :app:assembleDebug        # 编译 APK
gradlew.bat :app:connectedDebugAndroidTest  # 可选：连接测试设备验证账号/历史持久化

# macOS / Linux
./gradlew :app:testDebugUnitTest
./gradlew :app:assembleDebug
```

- **先配置 SDK 路径**：复制 `local.properties.example` 为 `local.properties`，
  把 `sdk.dir` 改成自己的 SDK 目录，例如 `sdk.dir=E:/Android/Sdk`
- **Android Studio Hedgehog (2023.1)+，Gradle JDK 必须是 17 或 21**
  （Settings → Build Tools → Gradle → Gradle JDK → 选 `jbr-17`）
- AGP 8.7.3、Gradle 8.10.2、compileSdk 34、targetSdk 34、minSdk 21
- 需要 SDK Platform 34 + Build-Tools 34.0.0（Studio 会提示自动安装）
- 手边没有 SDK 时，可以先跑一遍离线符号自查（需要 Python 3 + `pip install javalang`）：
  ```bash
  pip install javalang
  python3 tools/java_static_check.py
  ```
  它会检查“找不到符号”（未定义的本地方法/字段、`类名.成员`、`变量.成员`、`import com.zxw...`）、
  部分方法及本仓库构造器的参数个数、常量是否拼错等；**不检查类型兼容性或 Android API**，不能替代真正的编译。
- 依赖：CameraX 1.1.0、ML Kit Pose Detection 18.0.0（离线模型，画面不上传）

> **不会覆盖手机上已安装的正式版**：debug 包的 `applicationId` 是 `com.zxw.dev`
> （见 `app/build.gradle` 的 `applicationIdSuffix '.dev'`），安装后与正式版并存，
> 桌面显示为「BLE助手·测试」。两个包的私有数据隔离，正式版的历史录像不会自动出现在测试版；
> 可在测试版录制新的视频后回放验证。只有 `assembleRelease` 生成的包才会替换正式版。

> 遇到 `No matching variant of com.android.tools.build:gradle` 这类报错，基本都是
> **Gradle 用的 JDK 版本不对**（JDK 8/11 不行，需要 17/21）。
> 逐步排查见 [docs/fitness-module.md 第 7.1 节](docs/fitness-module.md#71-常见构建错误)。
