# 靠墙倒立算法

> [算法索引](README.md) · [人体骨架](pose-estimation.md) · 类型 `WALL_HANDSTAND`，主成绩为最长单组有效时间；不支持个人校准。该模式与[自由倒立](handstand.md)共用 `HandstandTimer`。

## 当前实际算法

| 项目 | 靠墙倒立的代码值 | 说明 |
| --- | --- | --- |
| 倒置 | 肩 y 比髋大 `0.02` 个画面宽单位以上；至少一只可信脚踝，所有可信脚踝高于肩 | 另一脚不可见时无法确认其位置 |
| 竖直度 | 躯干与竖直方向 `≤32°` | 自由倒立阈值为 `25°` |
| 髋横向漂移 | 最近最多 12 帧峰峰值 / 平均躯干长度 `≤0.30` | 自由倒立为 `0.18`；不足 3 帧暂不以漂移否定 |
| 起算 / 宽限 | 合格候选 `300 ms` / 通常 `700 ms` | 候选段计入，失效段不计入；起算后第一失效帧有下述例外 |
| 脚踝稳定代理 | 窗口中脚踝代表点 x 峰峰值 / 平均躯干长度 `≤0.25` | 只是“脚踝横移小”，**不是墙面接触检测** |

起算帧当前未设置 `lastGoodMs`；紧接的失效帧可能直接结束本组。起算后由相邻合格帧累计有效时间；主成绩显示最长单组，训练详情另显示本组、累计、组数、稳定度及贴墙代理比例。汇总保存最长、累计、稳定度和贴墙标记，但不单独保存组数或比例数值。

## “贴墙比例”到底是什么

`wallFrames` 在有有效身体度量且脚踝漂移满足 `≤0.25` 时增加；它**也会包含起算前或非保持姿势的这类帧**。`holdFrames` 只在起算后合格保持帧增加。界面比例为 `min(1, wallFrames / holdFrames)`，没有保持帧时为 0；保存记录时比例 `≥50%` 会保存贴墙标记。

这个比例的分子与分母并非严格同一帧集合，且脚踝静止不等于靠墙。它**不参与倒立有效计时的门槛**，不检测墙的位置、脚或背是否碰墙，也不能判断是否真的获得支撑。自由倒立时脚踝稳定也可能出现高比例；UI 上的“贴墙”只能当粗略代理。动作列表的“离开墙面或脚落地即结束计时”是目标描述，并非当前实现的接触检测。

## 适用场景与优缺点

- **适合**：在真实墙面附近、手机固定并完整拍到人体/脚踝的单人辅助计时；墙的安全性和人员保护需人工确认。
- **优点**：相比自由倒立放宽躯干倾角和髋漂移阈值，能分开记录本组/最长/累计，并提供可解释的脚踝稳定信号。
- **缺点**：没有墙面/接触模型；现有“贴墙比例”可能被起算前帧影响并高估。遮挡、单侧脚踝丢失、帧率、镜头晃动、尺度变化和人体侧别跳变均影响结果；不能作为安全证据。

## 与同类方案比较

基于脚踝稳定的规则无需额外器材但缺乏接触证据。墙面/脚部检测或多摄像头可研究人与墙的几何距离，仍会受深度、遮挡与标定影响；墙面或脚部压力/接触传感器能提供更直接的接触信号，但要安装和同步。视频姿态分类器同样需要标注验证，不应把“看着像靠墙”当作真实支撑。通用比较见[索引](README.md)。
