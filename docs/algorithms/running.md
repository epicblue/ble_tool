# 跑步计步算法

> [算法索引](README.md) · [人体骨架](pose-estimation.md) · 类型 `RUNNING`。输出为步数与估计步频，并粗略标注走/跑；适用于人在镜头内的原地跑或踏步，不测距离、速度或配速，也不支持个人校准。

## 输入与步骤

需有可信的同侧肩髋、左右两个脚踝，且髋在肩下。设 `s` 为躯干尺度，画面 y 向下：

```text
signal = (右脚踝 y − 左脚踝 y) / s
signal ≥ +0.16：一侧高；signal ≤ −0.16：另一侧高；其余为中间位
```

1. 第一侧信号只建立参照和时间，不补记第一步。
2. 符号翻转时，**上一侧**须连续出现至少 `2` 帧才视作可信；符合时，距离上一次参考/计步时间在 `180–1600 ms`（含边界）才增加一步，并记录间隔。不是说新的一侧也必须先维持 2 帧才立即计步。
3. 间隔过短过滤为高频变化；超过 1600 ms 的翻转只更新参考时间，不补步。左右脚踝或有效身体长期缺失超过 `700 ms` 时重置侧别、步频和髋部窗口，恢复第一帧不补步。
4. 最近最多 `10` 个已记录步间隔的平均值用于 `步频 = 60000 / 平均间隔(ms)`；单纯停止但人体仍可见时，历史间隔不会立即清空，因此旧步频可能暂时保留。
5. 已累计至少 2 步且有步频时：`≥150` 步/分标“跑”，`≤120` 标“走”；中间区间看最近最多 `20` 帧髋部 y 峰峰值 / 当前躯干，`≥0.05` 标“跑”。不足 4 个髋样本时以 `135` 步/分作中间区间备用分界。

## 优点、缺点与适用场景

- **优点**：只需相机；高度差、前一侧连续帧和时间门槛抑制一部分站立晃动；长期缺脚后不把恢复首帧算一步。
- **局限**：走路、跑步和踏步都可能触发；“走/跑”只是步频与髋起伏规则，**没有真正检测腾空或足底接触**。单脚动作、脚踝遮挡、低帧率、多人进入、快速摇晃或手机移动均可能导致漏计/误计。连续帧条件依赖实际采样率；不能保证所有高频抖动都被排除。
- **场景**：固定手机、全身和双脚同时入镜、活动范围有限的室内原地练习；人在画面外移动的户外跑步不适合本实现。

## 与同类计步方案比较

手机/手表 IMU 计步不要求双脚始终入镜，适合移动中的日常活动，但受佩戴方式、动作类型及设备实现影响，未必能识别动作姿势。视频时序模型可以研究更复杂的步态，但需要标注、算力和验证。压力鞋垫或足底传感器可提供更直接的接触信息，增加穿戴与同步成本。相关方法及资料见[索引](README.md)；项目尚未进行同设备对照。
