## 共用约定

- **坐标**：模型返回摆正后的图像坐标；项目把 `x、y、z` 都除以图像宽 `W`，图像 `y` 向下为正。`0.02` 这类直接比较坐标的阈值是**画面宽的比例**；文中标记为“倍躯干”的值才是除以 `bodyScale` 的比例。角度是二维投影角，不是真实三维关节角。
- **人体尺度**：`bodyScale = max(0.04, 肩代表点到髋代表点的二维距离)`；两侧可靠程度接近时使用中点，否则可能选择同一可信侧。它有助于减小缩放影响，但不能消除透视、遮挡或人体在画面中太小的问题。
- **可信度与侧别**：`BodyMetrics` 和 `PoseMath` 默认使用 `0.5`；身体度量需要至少一侧肩、髋同时可靠。两侧可信度差超过 `0.25` 时倾向可信侧，角度相差超过 `35°` 时不直接平均。数值是模型的入画估计，不等同于定位精度。侧别阈值附近缺少迟滞，指标可能跳变。
- **训练数据路径**：越界过滤 → 横滚补偿 → 按关键点滤波 → 动作判定。实时画面展示未经应用层滤波的模型点；录制文件保存滤波后的 17 点。有视频时回放默认重新抽帧识别，可对比新原始、新滤波和录制骨架；重识别无历史重力对齐。详见[人体骨架文档](pose-estimation.md)。
- **计时**：`HoldClock` 在相邻处理帧均合格时累计有效时间；候选姿势达到起算时长后会把候选段计入。失效帧暂停累计，宽限期用于决定是否结束当前组，不意味着失效期间仍在计时。`FrameGapGuard` 在相邻帧间隔 **大于** 500 ms 时先通知一帧失效；是否结束一组或丢弃动作，仍取决于各判定器自己的阈值。
- **个人校准**：支持俯卧撑、折凳俯卧撑、不标准俯卧撑、深蹲和引体向上；其他计时动作和计步不支持。先建立起始位，再在当前最佳位置确认：成功时立即计一次，保存账号/动作/折凳变体对应的目标，回到起始位后才能再次计数。目标大致取采样幅度的 95%，并有限幅和稳定性检查；它是个人目标，**不是标准或安全认证**。历史保存目标快照和组内事件，但历史回放仍使用当前版本重算。

## 同类动作识别方法如何评价

以下是工程选型比较，**不是在本项目设备和数据上的准确率排名**；模型和动作判定是不同层，换姿态模型不会自动解决计数或动作质量问题。

| 方法 | 长处 | 代价 / 边界 | 比较适合 |
| --- | --- | --- | --- |
| 本项目的 2D 关键点 + 几何阈值 + 状态机 | 本地、轻量、每个判据可解释；可按动作校准 | 依赖关键点、机位与规则；阈值难覆盖所有人；无法证明接触或安全 | 单人、固定手机、明确选择动作的辅助记录 |
| 单一关节角阈值 / 峰谷计数 | 更容易部署、调试 | 容易被遮挡、透视和阈值附近抖动影响；难区分动作质量 | 机位固定且动作简单的计数原型 |
| 视频时序 / 自相似计数，如 RepNet、TransRAC | 可研究较少依赖手写动作阶段的重复计数 | 需要视频时序、模型部署及数据验证；周期不等于姿势正确，对静止保持类不直接适用 | 多动作、周期性运动的研究或离线分析 |
| 关键点时序分类模型（如 LSTM / Transformer） | 可利用多个关节与历史轨迹，适合识别复杂阶段 | 需要有代表性的标注数据、训练、设备性能和解释性评估；域外泛化不保证 | 动作种类多且有训练/评测数据时 |
| 可穿戴 IMU / 压力传感器或多摄像头 | 分别可提供不受视觉遮挡的运动信号、接触证据或多视角 | 需要佩戴、同步或安装；IMU 有漂移和佩戴位置影响，多视角需标定；仍须验证 | 需长期运动、接触判断或更细致分析的场景 |

代表性资料：RepNet 官方实现 [1](https://github.com/google-research/google-research/tree/master/repnet)；TransRAC 官方实现及评价设置说明 [2](https://github.com/SvipRepetitionCounting/TransRAC)；以关键点时序和角度进行动作分类的示例研究 [2](https://arxiv.org/html/2411.11548v1)；摄像头与 IMU 的互补及局限 [12](https://arxiv.org/html/2512.21209)。这些论文和实现的结果不能直接移植到本项目。

## 验证口径与复现

现有 Java/JUnit 与 Python 回归主要使用**合成关键点**；本次深蹲横移改动后的离线运行结果分别为 `75/75`、`134/134`，不代表人体识别准确率、动作识别率或设备性能。部分 Android 代码曾用 API 存根做类型检查，录制/回放测试也曾在模拟环境运行；**完整 Gradle 构建、真实相机/录制和真机准确率仍待验证**。

```text
python3 tools/algo_sim/regression.py
python3 tools/java_static_check.py
# Windows，已配置 Android SDK 与 JDK 后：
gradlew.bat :app:testDebugUnitTest
```

真实评估建议先获得参与者同意，固定标注规则和动作标准，分别采集前/后摄、正/斜/侧面、不同距离/光照、遮挡和快慢动作；划分不同参与者的开发集与测试集。分别统计：

1. 左右肩等关键点相对人工标注的误差、静止段抖动、点丢失与左右身份切换；
2. 次数误差、误计/漏计、动作完成时间偏差及不标准原因的混淆情况；
3. 有效时长误差和休息是否被计入；
4. 模型推理延迟、回调间隔、预览叠加错位、视频/骨架起点与镜像；
5. 模型版本、设备、分辨率、温度、运行后端及帧率。与其他模型对比时保持数据、标注、设备和统计方式一致。

采集应尽量本地化并约定保存期限。原 MP4 导出不含屏幕骨架；如需复核实时标记，应经同意录制训练界面的屏幕。
