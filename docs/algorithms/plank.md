# 平板支撑算法

> [算法索引](README.md) · [人体骨架](pose-estimation.md) · 类型 `PLANK`，主成绩为最长单组有效时间；不支持个人校准。

## 输入和开始条件

使用肩、髋、手腕、脚踝的二维点，按可信侧生成身体代表点。以下条件同时满足时进入候选：

| 条件 | 当前值及含义 |
| --- | --- |
| 躯干接近水平 | 肩—髋与水平夹角 `<30°` |
| 手腕相对肩低 | `(腕 y − 肩 y) / 躯干长度 >0.05` |
| 髋比脚踝高 | 需至少一侧可信脚踝，`髋 y < 踝 y − 0.02`；`0.02` 是画面宽单位 |
| 身体直线代理 | 髋到肩—踝直线的距离 / 躯干长度 `≤0.15` |

若直线代理为 `NaN`，当前代码将 `aligned` 视为通过；这只是缺省处理，不代表身体确实直。算法不检测小臂、手掌或脚是否实际接触地面。

## 计时与输出

- 合格候选保持 `500 ms` 后开始，候选段记入有效时间。之后 `HoldClock` 只在相邻处理帧合格时累计；失效段不计入。
- 姿势破坏后通常有 `800 ms` 宽限，恢复可继续同组；人体丢失超过 `600 ms` 后进入中断处理。当前开始计时的那一帧**没有设置** `lastGoodMs`：若紧接着出现姿势不合格帧，可能直接结束而不是享受完整宽限，需真机/回归覆盖。
- 髋偏移超限时优先提示并暂停累计；按累计塌腰帧计数，第 1、16、31……个此类帧增加一次提醒，**不是严格每秒一次**。
- 主成绩是最长单组；训练详情显示本组和组数，内部也累计总有效时间。汇总保存最长、累计及稳定度，组数不是独立的持久化字段。稳定度为 `goodFrames / (goodFrames + sagFrames)`，统计口径是代码中对应的帧，不是精确的全程时间比例或人体平衡测量。

## 场景与优缺点

- **适合**：固定侧面或斜侧面镜头，肩、髋、脚踝和手腕尽量入镜，想记录保持时间的单人训练。
- **优点**：无需设备；候选时长、失效暂停和宽限减少一部分瞬时误报；髋偏移有可解释提示。
- **缺点**：侧身遮挡、倾斜、身体前后方向变化可能使二维直线失真；脚踝或腕点不足、手机晃动及帧率变化影响结果。不能证明实际支撑、肌肉受力、动作规范或安全；“稳定度”不等于专业姿势评分。

## 同类方法比较

单帧肩髋踝角或单一静态分类器更简单，但容易在阈值附近闪烁；当前增加候选时长、时间累计和直线距离，仍依赖关键点准确。多视角/深度或穿戴 IMU 可提供额外姿态线索，成本是标定、佩戴与同步；压力传感器可提供接触证据。时序模型需姿势质量标注，不能假设对所有人更可靠。详见[方法比较](README.md)。
