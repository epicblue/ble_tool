# 深蹲算法

> [算法索引](README.md) · [人体骨架](pose-estimation.md) · 类型 `SQUAT`，主成绩为有效次数；可设置个人目标。以下为默认未校准规则。

## 输入和实际流程

使用肩、髋、膝、踝点；膝角是髋—膝—踝的二维夹角，髋下降量以观察到的站立位为参考并除以躯干长度。

1. **站姿门槛**：髋必须在肩下方至少 `0.02` 个画面宽单位；可用脚踝不应明显高于髋。至少需要一侧可计算的膝角。
2. **站立基准**：默认膝角 `≥155°` 时更新站立髋高度。膝角及髋高度还有 `0.5` 系数平滑；相对于站立髋的下降量用于后续深度判断。
3. **往返阶段**：平滑膝角 `<140°` 开始下蹲，回到 `≥155°` 后结算；阶段 `<320 ms` 忽略。膝/脚踝或人体长期不可用超过 `500 ms` 会放弃未完成的阶段。
4. **到位与最低位移**：最小膝角 `≤100°` **或**最大髋下降 `≥0.35` 倍躯干，视作默认深度到位；但仍要求髋下降 **至少 `0.12` 倍躯干**，否则不计数。明显下蹲的参考是膝角 `≤125°` 或髋下降 `≥0.18` 倍躯干。
5. **姿势与结果**：本次躯干相对竖直的最大倾角 `>55°` 可记为姿势问题；有足够髋移动但深度或姿势不足时可记为不标准，过小、未完成或部分姿势异常阶段可能被忽略。记录有效数、不标准数及提示。

个人校准使用连续三帧建立保守起始基准，并检查当前原始/滤波测量的差异及最小移动；成功立即记一次并保存个人深度、起始角、最低移动量和前倾容忍，回到个人站立门槛才能继续。它不是医学或安全标准。

## 疑似骨架冻结时的恢复

- 训练恢复为 ML Kit Accurate `STREAM_MODE` 连续跟踪，以及所有动作共用的旧逐点 `PoseSmoother`；不再提供上次的逐帧找人选项，也不再进行整体横移滤波。
- 仅深蹲检查**滤波和重力旋转前**的原始坐标，与屏幕上的点相同。17 个显示点均须入画且置信度 ≥0.5，肩、髋、膝、踝完整；点集合与画面尺寸须保持不变。连续至少 8 帧、2 秒，帧间隔 ≤500ms，恰有 1–2 点相对起点位移 ≥0.015 个画面宽，至少 15 点位移 ≤0.0004 个画面宽，且没有介于两者的点，才尝试重新找人。时间回退、重复、丢点、低置信或画面尺寸变化会清除证据；每次尝试后冷却 8 秒。
- 新建一个 `STREAM_MODE` 检测器处理同一画面。候选至少 8 个可靠点，且一侧肩/髋/膝/踝完整，并有至少 3 个原先静止点产生 ≥0.0025 个画面宽的变化才替换旧跟踪器；仅检测到腿、未改善或推理失败时继续使用原跟踪。训练成绩和个人校准不主动清空。App 自己不会在平时每帧重建检测器，ML Kit 内部的跟踪行为仍由 SDK 决定。
- 这些阈值是保守的启发式，**不证明发生了模型冻结或找到了同一个人**：正常单肢动作也可能具有相似轨迹，轻微抖动、遮挡或慢帧则可能使真实冻结漏检。候选即使通过也未保证点位准确；多人同框尤其可能换人。尚无该设备的轨迹与准确率验证。
- 原有滤波仍会对大跳变等待稳定后重捕获，实时骨架显示原始点。新版本录制逐帧结果，同版回放无需重算；旧版或损坏时回退。手动视频重识别无训练时的横滚补偿和组内校准事件，只供对比。

## 适用场景与优缺点

- **适合**：单人站立/下蹲、固定手机、肩髋腿和脚踝清楚可见；可分别尝试正、斜、侧面并以真实结果选择机位。
- **优点**：膝角与髋位移互补，额外设置最小髋移动来抑制只抖膝的误计；时间/状态门槛可抑制部分噪声，支持个人目标。
- **缺点**：二维膝角与髋下降并不等同于三维蹲深或“大腿一定水平”；`或`条件在一路错误偏大时可能误判。相机移动、骨架跳动、近身遮挡、人体尺度变化、角度阈值和快速动作均可能影响计数。没有评估膝内扣、承重、足底接触或疼痛。

## 与同类方案比较

单膝角计数更简单，但更受遮挡/透视影响；本算法增加髋位移和最低移动门槛，代价是依赖稳定站立基准。多摄像头重建或穿戴 IMU 可补充空间信息，但需要同步、标定或佩戴，仍要对具体动作和人群验证；时序模型需要标注和部署资源，解释性也须设计。公开机位研究显示不同动作和机位可能有不同结果，不能把他人结果当作本项目性能 [12](https://mhealth.jmir.org/2026/1/e82412)。
