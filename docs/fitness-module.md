# 体能训练 · 摄像头姿态捕捉模块

在原有 BLE 助手的基础上新增的运动记录模块：用手机摄像头实时识别人体关键点，自动统计
**倒立 / 靠墙倒立坚持时间**、**折凳俯卧撑 / 俯卧撑 / 不标准俯卧撑个数**，并把每次训练
（视频 + 骨架数据）保存下来，可以随时回放；训练数据按账号隔离，支持账号切换。

入口：App 首页底部的「体能训练 · 摄像头动作捕捉」按钮。

> 每项动作的当前代码规则、人体骨架处理、优缺点及同类方案比较见 [算法文档索引](algorithms/README.md)。本文为功能概览；规则以对应动作文档和代码为准，合成实验不是手机实测。

## 1. 功能一览

| 功能 | 说明 |
| --- | --- |
| 动作识别 | Google ML Kit Pose Detection（离线，画面不出手机），CameraX 负责预览与录像 |
| 倒立 | 身体倒置 + 躯干接近竖直 + 保持稳定才计时；记录每组时长与最久一组 |
| 靠墙倒立 | 同倒立，倾斜容忍略放宽，并统计「贴墙」比例（双脚横向几乎不动视为贴墙） |
| 折凳俯卧撑 | 支持两种姿势：双手撑凳（上斜）、双脚垫凳（下斜） |
| 俯卧撑 | 肘部下放到约 90°、身体成一条直线才计有效次数 |
| 不标准俯卧撑 | 专门统计不标准次数，并给出原因：幅度不足 / 塌腰撅臀 / 跪姿 |
| 平板支撑 | 计时；塌腰/撅臀时暂停计时并提醒，累计"塌腰提醒"次数与稳定度 |
| 深蹲 | 计数；膝角 + 髋部下蹲量双判据，只抖膝不下蹲不计数，上身前倾过多记不标准 |
| 引体向上 | 计数；悬挂 → 拉起状态机，只弯手臂没上去不计数 |
| 靠墙蹲 | 各组有效时间实时累计；同时显示本组、最长单组与稳定度。膝角 60~110°、大腿水平、躯干竖直才计时 |
| 跑步计步 | 计数；左右脚踝交替离地 → 步数与步频，站着晃动与高频抖动不计数 |
| 实时反馈 | 可开关的关键点名称/置信度、跳变待定圈、场景诊断、深度进度条及动作文字提示 |
| 回放 | ① 视频回放（mp4，叠加骨架）② 纯骨架动画回放（在没有视频或视频损坏时兜底） |
| 回放控制 | 播放/暂停、拖动进度条、0.5x/1x/1.5x/2x 倍速、同动作记录上一条/下一条 |
| 视频导出 | 回放页用系统文件选择器保存原始 MP4，不包含骨架、标记或成绩叠加；仅有骨架时不可导出 |
| 历史记录 | 按动作筛选、缩略图、成绩、视频/骨架标记、删除（同时删除视频与骨架文件） |
| 账号 | 新建 / 重命名 / 删除 / 切换；每位使用者的历史记录、视频、个人校准完全独立 |
| 个人校准 | 按当前最佳动作记一次并保存幅度和已确认的姿势容忍；俯卧撑（含折凳/不标准）、深蹲、引体向上支持 |

## 2. 使用步骤

1. 打开 App → 底部「体能训练」。
2. 点右上角账号卡片可以切换/新建账号。
3. 选择动作。折凳俯卧撑会先让你选「双手撑凳」或「双脚垫凳」。
4. 把手机**竖直固定**（靠墙、三脚架均可），人离手机 3~4 米，**侧对镜头**，
   保证全身在画面内。
5. 点「开始训练」：开始录像、记录骨架并实时计数/计时。
6. 如需个人校准：先回到起始位，然后保持当前能做到的最好位置约半秒，让同伴点「个人校准 +1」。
   也可长按按钮启动 5 秒倒计时，独自训练时有时间回到起始位、摆好最佳姿势；倒计时内点按可取消。
   采样成功即记一次并保存当前用户和动作的目标；先回到起始位，再继续做下一次。
7. 点「结束并保存」：弹出成绩，可直接进入回放。
8. 首页「历史记录」里可以按动作筛选、回放或删除；账号页的「个人校准设置」可查看和重置。
9. 回放有视频的记录，点「导出视频」→「选择位置」，在系统文件选择器中指定文件名和保存位置，等待完成提示。

> 识别在手机本地完成（ML Kit 离线模型），App 不会自动上传画面；如果导出到云盘，所选文件提供方可能会上传副本。

### 2.1 看懂标记和场景提示

- 进入训练页后，不必先开始训练即可通过骨架调整机位。说明遮挡画面时可点「收起说明」；
  点「标记：开/关」控制名称、置信度和待定圈，关闭详细标记后仍保留基本骨架。
- **训练的“原始”**标记直接显示模型输出的 17 个主要点（鼻、左右肩/肘/腕/髋/膝/踝/脚跟/脚尖）：
  绿点 ≥50%，黄点 30–49%，标记的百分数是模型对关键点入画的估计，不是动作正确率。
  过低、越界或无效的点不画；紫圈表示该原始点的新位置被滤波器暂时拒绝，旧位置可能短暂保留。
- 每 250ms 左右更新场景提示：按当前动作检查相关部位缺失、出画、同侧关键点不完整，
  并提示人体过小或关键点靠近边界。顶部 `可靠点/12` 是左右肩、肘、腕、髋、膝、踝的数量，
  并非完整人体质量评分。画面暂停超过约 1.5 秒会清除旧骨架并提示检查相机；回调间隔过大时会提示识别偏慢、可能漏计或难以恢复。
- 深蹲在进入训练前可选择「逐帧重新找人」或「连续跟踪」。前者每帧重新检测人物、可能更慢；后者可能更流畅，但横移时跟踪区域可能跟错。训练或录像中不能切换，需退出后重选；顶部也显示当前模式。深蹲回调间隔 >350ms 时提示识别偏慢，回调间隔与判定所用的采集时间戳不一定相同。
- **回放的“录制滤波”**来自历史文件，不是当时的原始 33 点，也不含紫圈；有视频时默认重新识别，可切换「新原始」（带待定圈）、「新滤波」和「录制」。回放重算使用当前版本算法，成绩可能与保存时不同。
- 这些提示只根据单人的关键点推断，并不能识别多人身份、墙/凳或保证动作安全；同框多人、遮挡、低光仍可能误判。
  建议一次只有训练者入镜，按提示调整拍摄，并在真实设备验证视频与骨架是否对齐。

### 2.2 靠墙蹲时间与导出

- 靠墙蹲大号数字是**所有组的有效时间之和**，包含正在进行的一组。详情中「本组」是当前组，
  「最长单组」是本次最长的一组；短暂姿势不合格时暂停累计，恢复后重新增加，不把休息时间算进去。
  结束后保存累计和最长单组；首页的历史最佳仍按最长单组统计。
- 旧记录只有最长单组，没有保存累计。历史列表和无可用骨架的回放仍显示最长；
  若有录制骨架或视频重识别成功，可以按当前算法重算逐帧累计，但它不是当时保存的累计成绩。
- 系统文件选择器可选择手机或其他文件提供方；不需要新的存储权限。导出的只是原始摄像头 MP4，
  不包含屏幕叠加的骨架、关键点、场景提示和成绩，也不自动保证加入相册。
  导出不改动源文件；删除训练记录或卸载 App 不会删除用户自行保存的副本。
- 复制在后台进行；请保持应用运行直到完成提示。取消选择不会修改原文件，目标不可写、磁盘不足、
  提供方异常或应用被系统终止时可能留下空文件或不完整文件，需在选择的位置检查或删除后重试。

## 3. 判定规则

判定逻辑在 `com.zxw.fitness.analysis` 中，训练使用归一化关键点；回放基于记录的 17 个点，
用**当前版本**的判定代码重算。相同算法和校准事件下预期一致，但算法升级后历史回放的
次数/时长可能与历史记录保存的原成绩不同，不能保证跨版本完全一致。

### 3.1 俯卧撑类（`PushUpCounter`）

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `TOP_ANGLE` | 152° | 撑起位的肘角参考；阶段还使用深度信号 |
| `DOWN_START_DEPTH` | 0.22 | 默认幅度进度超过它开始记录一次下放（个人目标可动态调整） |
| `DEPTH_ANGLE` | 100° | 到位深度；折凳"手撑凳"放宽到 106° |
| `PARTIAL_ANGLE` | 122° | 明显下放的参考；手撑凳变体为 128° |
| `HIP_STRAIGHT_ANGLE` | 150° | 侧视时肩-髋-踝夹角低于它判定身体不直 |
| `KNEEL_ANGLE` | 120° | 膝角低于它判定跪姿 |
| `MIN_REP_MS` | 350ms | 短于它的往返视为抖动，不计数 |

- 深度取**两路信号里更深的那个**：`max(肘角深度, 手腕下降比例)`。
  合成横向缩放实验说明斜视时肘角可能失真；手腕相对肩高度是另一条辅助信号。真实透视和遮挡也会影响该信号，取较大值可能放大单路错误。
- 阶段切换使用当前深度；该深度来自已滤波的骨架，不是模型原始帧。额外平滑的深度主要用于进度显示。
- 只有躯干接近水平（与水平夹角 < 55°）且手腕相对肩高度满足门槛时才进入判定；这能排除部分站姿，但不能保证无误识别。
- 一次动作若姿势有问题（塌腰/撅臀/跪姿）→ 计入"不标准"；幅度不足 → 也计入"不标准"；
  两者都会累加"姿势提醒"次数。

### 3.1.1 识别增强（v1.2 起）

| 增强 | 说明 | 位置 |
| --- | --- | --- |
| 时序滤波 | 判定帧指数平滑；旧点最多保持 350ms，跳变阈值为 `max(0.12画面宽, 0.6×躯干长度)`；新位置通常须稳定 ≥700ms 且 ≥3 帧才重捕获。深蹲另支持多点持续一致横移后恢复，需满足关键点、间隔及丢失保护；实时骨架仍显示原始点 | `pose/PoseSmoother`、[深蹲算法](algorithms/squat.md) |
| 尺度归一化 | 多数比例量以"肩→髋长度"为基准，可减小一部分缩放影响，不能消除透视和小目标误差 | `pose/BodyMetrics` |
| 视角代理 | 按"肩宽/躯干长度"粗分侧视/正视；俯卧撑深度实际取肘角和手腕下降两路较大值，侧视时额外使用髋角 | `BodyMetrics.View` |
| 直线度用偏移量 | 髋偏离二维"肩-踝连线"的距离 ÷ 躯干长度（`sagRatio`），仍受视角及点误差影响 | `BodyMetrics.sagRatio` |
| 丢帧容错 | 俯卧撑短暂丢失时尝试保留阶段，超过 500ms 放弃未完成阶段；其他姿态门槛和帧间隔保护仍可能中断 | `PushUpCounter.DROPOUT_MS` |
| 稳定度评分 | 倒立/平板支撑记录晃动与竖直度，输出 0~100% 稳定度并存进历史记录 | `HoldAnalyzer.getStability` |
| 双侧可信度融合 | 关节角和躯干优先使用可靠的同一侧；两侧置信度相差 >0.25 时优先高的一侧，关节角相差 >35° 时也不硬平均 | `pose/PoseMath`, `pose/BodyMetrics` |
| 边界检查 | 判定前屏蔽异常及画面外的点；原始标记用于观察，避免越界的模型预测参与动作计算 | `model/PoseFrame`, `camera/CameraController` |
| 有效时间计时 | 计时类只累计"相邻两帧都合格"的时间；帧间隔 >500ms 按识别中断处理，回放使用相同规则 | `analysis/HoldClock`, `analysis/FrameGapGuard` |
| 关键关节丢失 | 深蹲的双膝、引体的双肘或跑步脚踝长期不可用后，丢弃未完成的动作状态；恢复首帧不补步 | `analysis/SquatCounter`, `PullUpCounter`, `RunStepCounter` |
| 横滚补偿 | 用加速度计估计的横滚角旋转判定点；合成旋转测试通过，方向和效果仍需真机验证 | `pose/GravityAlign` |

> 训练判定使用重力对齐与滤波后的每一帧；v2 骨架文件同时记录该帧的补偿角。
> 录制骨架回放用保存的处理帧重算成绩，并反向旋转以对齐视频；视频新识别没有可对齐的历史重力数据，直接使用视频坐标。两种回放都不读取当前传感器。
> 本次训练的初始个人目标和组内校准事件保存在历史记录；新识别仅使用初始目标，不重放旧帧下标的组内事件。新旧算法下的回放结果可能不同。
> 帧间隔超过 500ms 不把空白算成合格保持；设备持续低于约 2 帧/秒时计时或深蹲计数可能无法连续。深蹲重捕获还要求候选间隔不超过 350ms，慢设备可能难以恢复；需切换较快模式并真机验证，不应靠放宽帧保护补计。

#### 3.1.2 横滚补偿（`GravityAlign`）

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `DEAD_ZONE_DEG` | 0.8° | 小于它的横滚不补偿，避免正常手持时引入抖动 |
| `MAX_ROLL_DEG` | 60° | 超过它认为手机接近横放，不做补偿（补偿反而会放大误差） |
| `MIN_GRAVITY_XY` | 3.0 m/s² | 重力在画面上的投影小于它时（手机接近平放）横滚不可信，退化为不补偿 |
| `ROLL_SIGN` | +1 | 补偿方向系数；若真机上发现歪一点反而更歪，改成 −1 即可 |

- 角度来源：`Sensor.TYPE_ACCELEROMETER`（静止时读到的是"上方向 × 9.81"），
  `CameraController` 注册监听并每帧把 `rollDegrees` 带进处理；
- 公式：画面中"上方向"的方位角 `α = atan2(−ay, ax)`，需要旋转 `ψ = −90° − α`；
  手机拿正时 `ψ = 0`，顺时针歪 30° 时 `ψ ≈ −30°`；
- 补偿后所有"水平/竖直"判据（平板支撑的躯干水平、倒立/靠墙蹲的躯干竖直、前倾角）
  在估计的重力对齐坐标系里，但传感器误差、手机运动和补偿方向仍需真机验证；
- 设备没有加速度计时不补偿，行为与旧版本一致。

#### 3.1.3 个人校准（手动确认）

- 支持 **俯卧撑、不标准俯卧撑、折凳俯卧撑（手撑/脚垫分开）、深蹲、引体向上**；
  计时类和跑步计步暂不支持。先回到各动作的起始位，建立撑起/站立/悬垂基准，
  再到当前最佳位置并保持，点击按钮；起始位不要求达到标准伸直角度，会保存本组观察到的个人起始角。
  起始基准需要连续三帧确认以排除单帧误识别；缺关键点、没有新帧、滤波帧与当前原始姿态偏差过大或几乎没有移动时会拒绝，显示原因。
- 点成功后**立即记一次**，并保存当前帧的幅度、髋偏移/前倾等个人容忍度；
  同一往返必须回到起始位才允许再次计数，即使中间丢帧也不会重复记。
  「不标准俯卧撑」的主成绩是不标准次数，因此按钮记入不标准次数。
- 后续往返按个人目标判到位；使用归一化的角度/位移最大值，目标留 5% 抗抖余量。
  已确认的跪姿或不够直等姿态可按个人目标计数，但仍累计姿势提醒；超出已保存容忍度的动作仍会提示或记不标准。
  最小的下蹲/上升位移和姿态门槛仍然存在，防止把站立或抖动校准成动作。
- 不同账号、动作及两种折凳姿势完全分开；下一组自动加载。账号页可按动作查看参数或恢复默认，
  重新校准会覆盖当前账号该动作的旧目标。历史回放保留当时的目标快照与每次按钮事件，
  后来重新校准或重置不会改写已保存的旧成绩；算法升级后回放重算值可能不同。
- 这是用户确认的**个人训练目标，不代表标准或安全姿势**；有疼痛、眩晕或不适时应停止。
  尚未实现无需点击、自动学习前两次往返的 ROM 自校准。

### 3.2 倒立类（`HandstandTimer`）

- 倒置：肩膀低于髋部；至少一侧脚踝可靠可见，所有可靠可见的脚踝都要高于肩。
  遮挡另一只脚踝时只能根据可见的一侧判断，不能证明双脚都在肩上方。
- 竖直：躯干与竖直方向夹角 ≤ 25°（靠墙倒立放宽到 32°）。
- 稳定：最近最多 12 帧的髋部横移 / 平均躯干长度 ≤0.18（靠墙 0.30）。
- 同时满足并维持 300ms 起算；通常有 700ms 宽限，失效时间不计入。起算后第一失效帧可能因 `lastGoodMs` 尚未赋值而直接结束。成绩取最长单组，并记录累计。
- 靠墙模式统计脚踝横移 ≤0.25 倍躯干的代理比例，比例 ≥50% 时保存贴墙标记；它不是真实墙面/接触检测，分子还可能包含保持前的帧，也不作为计时条件。

### 3.3 平板支撑（`PlankTimer`）

- 撑地：躯干与水平夹角 < 30°，手腕在肩下方；
- 直线：`sagRatio ≤ 0.15`；超过时暂停计时，按塌腰帧数每 15 帧增加一次提醒（首帧即提醒），并非固定每秒。
- 保持 500ms 后起算；通常有 800ms 宽限，失效段不计时。起算后首个姿势不合格帧可能因 `lastGoodMs` 尚未赋值而直接结束。
- 有效时间由 `HoldClock` 累计（相邻两帧都合格才计时）。合成实验中 800ms 宽限期内塌腰 600ms：
  修复前显示 3.9 秒，修复后为 3.2 秒；
- 稳定度 = 有效帧 /（有效帧 + 塌腰帧）；
- `getInterruptMs()` 基于最近合格帧估算当前组的中断时长；正在宽限期的最新一段不一定已包含，结束后返回 0，不能视为持久化的完整休息时间。

### 3.4 深蹲（`SquatCounter`）

- 站姿门槛：髋在肩下、脚踝在髋下（俯卧/倒立时不计）；
- 下蹲：平滑膝角（髋-膝-踝）< 140° 开始，最小膝角 ≤100° 是到位判据之一；
- **到位判据取"膝角"或"坐髋"之一**：膝角 ≤ 100°，或者髋部下降 ≥ 0.35 × 躯干长度
  （`HIP_TRAVEL_DEEP`）。合成横向缩放实验表明只靠膝角可能漏计；真实机位下仍需验证；
- **最低髋移动门槛**：未校准时髋下降须 ≥0.12 × 躯干长度，否则不计数；髋下降 ≥0.18 或膝角 ≤125° 是明显下蹲的参考。
- 上身前倾 > 55° 记为不标准（"上身过度前倾"）。

### 3.5 引体向上（`PullUpCounter`）

- 悬挂：手腕比肩高 ≥ 0.15 × 躯干长度（`wristDropRatio` 为负）；
- 拉起：肘角 ≤95° 且身体相对悬垂位上升 ≥0.10 × 躯干长度，默认算到位；
- 只弯手臂、身体没上去 → 不计数（判为"幅度不足"）；
- 建议画面拍到横杆、双手与全身；当前算法不检测横杆，也不能确认下巴是否过杆。

### 3.6 靠墙蹲（`WallSitTimer`）

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `MIN_KNEE` / `MAX_KNEE` | 60° / 110° | 有效坐姿的膝角范围：更小接近跪姿，更大说明站起来了 |
| `MAX_THIGH_RISE` | 0.30 | 髋膝高度差 ÷ 躯干长度，超过说明大腿没水平（半蹲） |
| `MAX_TORSO_LEAN` | 30° | 躯干与竖直方向夹角上限；不证明是否贴墙 |
| `ARM_MS` / `GRACE_MS` | 400ms / 800ms | 稳定多久后开始计时 / 条件破坏后的宽限期 |
| `DROPOUT_MS` | 600ms | 允许的人体丢失时长 |

- 必须与站立区分：髋在肩下（`hipBelowShoulder`）且膝角落进 60~110°；
- 大腿没到水平、或躯干不够竖直 → 不计时，界面提示具体原因（"臀部再往下坐" / "上身贴住墙"）；
  髋膝高度差只使用可信膝点，一侧被遮挡时不会把另一侧无效坐标算进去；这里不能真正判断墙面接触。
- 每组结束时把该组有效时长加入累计，进行中也实时加上本组；界面区分累计、本组与最长单组。
  起算帧即作为最近合格帧，刚起算后短暂不合格仍享有宽限期；暂停/休息区间不计入；
- 稳定度 = `1 − 保持过程中膝角标准差 / 20°`，抖动越大分数越低，存进历史记录。

### 3.7 跑步计步（`RunStepCounter`）

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `SIGNAL_ON` | 0.16 | 触发一步所需的左右脚踝高度差（×躯干长度） |
| `MIN_STEP_MS` / `MAX_STEP_MS` | 180ms / 1600ms | 步频上下限（≈333 步/分 ~ 37 步/分） |
| `MIN_STABLE_FRAMES` | 2 | 一侧至少连续保持 2 帧，翻转才算一步 |
| `DROPOUT_MS` | 700ms | 人体丢失超过它则重置左右侧状态 |
| `INTERVAL_WINDOW` | 10 | 计算平均步频时保留的最近间隔数 |
| `RUN_CADENCE` / `WALK_CADENCE` | 150 / 120 步/分 | 步频高于/低于该值直接判为跑步/走路 |
| `HIP_BOB_RUN` | 0.05 | 步频落在 120~150 之间时，用躯干起伏（×躯干长度）区分跑/走 |
| `BOB_WINDOW` | 20 帧 | 统计躯干起伏的滑动窗口 |

- 信号 = `(右脚踝 y − 左脚踝 y) / 躯干长度`，正值表示左脚更高；第一侧建立参照，满足持续帧和时间门槛的翻转才记一步；
- 站着不动、轻微晃动（信号不到 `SIGNAL_ON`）不计数；
- 连续帧和最短间隔可以过滤部分高频抖动，但不能保证排除全部抖动；
- 有效翻转间隔超过 1.6 秒时更新参考但不补步；脚踝长期丢失后清除旧侧与步频窗口，恢复首帧不补步。单纯停止但脚踝仍可见时旧步频不会立即清空；
- **走 / 跑分类**：脚踝交替的模式走和跑几乎一样，所以用"步频 + 躯干起伏"区分 ——
  步频 ≥150 判跑步、≤120 判走路、中间区间看躯干起伏是否 ≥0.05；这只是代理，没有检测足底接触或真实腾空。
  合成示例：慢走 90 / 快走 120 → 走路；慢跑 160 → 跑步；135 步/分 + 起伏 → 跑步，无起伏 → 走路；
- 界面额外显示"跑步 / 走路"与步频（`getGaitText()` / `getDetailText()` / 历史记录详情），单位是"步"；
- 要求双脚（尤其脚踝）在画面内，原地跑或面向/侧对镜头跑都可以。

> 阈值都可以在对应类顶部的常量处调整，建议先在真实场地上用 `Logcat`/界面提示校准。

## 4. 数据存储

所有数据都在 App 私有目录，卸载即清除：

```
files/fitness/<userId>/sessions.json      # 训练汇总（成绩、时间、文件名）
files/fitness/<userId>/media/<id>.mp4      # 录像（若设备支持三路同开）
files/fitness/<userId>/media/<id>.jpg      # 缩略图
files/fitness/<userId>/media/<id>_pose.dat # 骨架数据（二进制）
```

账号列表与每个账号的 `calibrations` 保存在 `SharedPreferences`（`fitness_users`），
当前账号 key 为 `current_user`。`sessions.json` 为每组另存 `initialCalibration`
和以骨架帧下标定位的 `calibrationChanges`，不依赖后来修改的个人设置。
计时类新记录在 `holdMs` 保留最长单组（兼容历史最佳统计），另写 `totalHoldMs` 保存所有组有效累计；
旧记录没有 `totalHoldMs` 时保持未知，不把 `holdMs` 解释成累计。组数没有写入历史汇总。

骨架文件格式（`PoseLogWriter` / `PoseLog`）：

```
int  magic = 0x504F5345 ("POSE")
int  version = 2          // 读取器同时兼容旧版 v1（原始像素，无 roll）
int  viewWidth            // 摆正后的分析画面宽
int  viewHeight
重复 N 次:
  int   timeOffsetMs      // 相对第一帧
  byte  visible           // 是否检测到人体
  float rollDegrees       // v2 新增：本帧施加的横滚补偿角
  17 × 4 × float          // 处理后的 x, y, z, confidence（见 PoseFrame.LANDMARK_SUBSET）
```

历史骨架只保存 17 个滤波后关键点，不保存训练画面中的原始 33 点或跳变待定状态；
v2 的 x/y/z **都除以画面宽度**，保持几何角度不失真；绘制时再乘回画面宽。
旧 v1 保存的是像素坐标，读取后按像素绘制；旧文件没有横滚角，无法恢复当时未经旋转的骨架。
每一帧都记录以便与实时计数、校准事件一致；30fps 下 5 分钟约 2.5 MB（不含视频）。

## 5. 回放实现

- **有视频：默认从视频重新识别**。`VideoPoseReanalyzer` 后台用 `MediaMetadataRetriever.OPTION_CLOSEST` 顺序提取 MP4 画面（请求时间附近的帧），每张送入与相机共用的 ML Kit Accurate 检测器和 `PoseFrameConverter`。深蹲用 `SINGLE_IMAGE_MODE` 每张重新找人，其他动作使用 `STREAM_MODE`；每次任务创建独立检测器，并不是读取旧 PoseLog 充当新识别。
- 默认每 100ms 抽一帧，最多 6000 帧；更长视频自动增至最多 350ms，超过 35 分钟报错并回退。画面长边最多缩到 960 像素，抽帧比例与已知视频元数据不符或中途比例改变时停止重识别；丢帧保留空帧并提示。90°/270° 视频只有在编码宽高和抽帧宽高明确表明仍未旋转时才补转，避免对已摆正画面重复旋转；方形、180° 和异常元数据无法仅靠比例判断，仍需设备验证。任务内存有限、可取消、离开页面停止；在途 ML Kit 完成后才释放位图/检测器，切换记录的旧回调不能覆盖新记录。等待期间可以取消并播放录制骨架，失败也可重试。
- 新识别依次保留原始点、越界屏蔽后的 `PoseSmoother` 输出和待定标记，`ReplayTimeline` 计算各动作；默认显示新滤波，回放按钮可在「新滤波 → 录制骨架 → 新原始」之间循环切换。`PoseVideoView`（`TextureView` + `MediaPlayer`）按视频时间查索引，支持暂停、拖动和倍速；采样间隔、非关键帧近似抽取、播放器 seek 和设备旋转/镜像会影响对齐，不能保证逐帧精确。
- **结果仅临时驻留内存，不写回原视频、骨架文件、历史成绩或个人设置。** 新识别的判定使用训练开始时的个人目标，但历史组内校准事件只有旧骨架帧下标、录像与骨架的起点也未同步保存，因此不能精确重放；重识别也没有与视频时间准确对应的重力数据，不做横滚补偿。计数仅供验证对比，不等同当时实时训练结果；界面另显示历史保存成绩。
- **录制骨架模式**仍用原来的 `PoseLog`：v2 逐帧逆旋转用于显示，原先重力对齐坐标用于判定，个人校准事件仍按旧帧下标重放。旧 v1 没有横滚角。视频与首个旧骨架帧起点不一定相同，可能错位。
- **无视频**时仍用 `SystemClock` 驱动纯骨架动画，暂停、拖动和倍速可用；无骨架时显示已保存成绩，旧靠墙蹲没有累计时只显示最长单组。
- 导出使用 `ACTION_CREATE_DOCUMENT` 获取目标 URI，后台分块复制 App 私有的**原 MP4**，不含任何新旧骨架；不需要额外存储权限。选定的账号、记录和视频文件在启动选择器时固定；切换回放记录不会改变当前导出源。失败不擅自删除所选文件，可能留下部分文件；请用户自行检查。此路径尚需真机验证。

### 7.1 测试包与正式版共存（不覆盖已安装的程序）

Android 靠 **applicationId（包名）** 区分应用：包名相同就会被当成同一个 App。
仓库里的人 `defaultConfig.applicationId = "com.zxw"` 与正式版一致，为了测试时不覆盖它，
`app/build.gradle` 的 `debug` 构建类型里加了后缀：

```gradle
buildTypes {
    debug {
        applicationIdSuffix '.dev'      // 测试包 = com.zxw.dev
        versionNameSuffix '-dev'
    }
}
```

效果：

| 构建方式 | 包名 | 桌面名称 | 是否影响已安装的正式版 |
| --- | --- | --- | --- |
| `assembleDebug` / Studio 的 Run | `com.zxw.dev` | BLE助手·测试 | 不影响，两个 App 并存 |
| `assembleRelease` | `com.zxw` | 蓝牙BLE助手 | **会**替换正式版 |

- 两个包的数据目录完全独立，卸载测试包不会清掉正式版的 BLE 配置与训练数据。
- 桌面名称的差异来自 `app/src/debug/res/values/strings.xml`（debug 源集覆盖 `app_name`），
  删掉这个文件就只有包名不同、名字一样。
- 如果确实想让测试包就是正式包本身（覆盖安装），把 `applicationIdSuffix '.dev'` 那一行删掉。
- **安装命令**：`gradlew.bat installDebug`（或 Android Studio 直接 Run）。
  不要装 `app/build/outputs/apk/release/app-release.apk`，那会覆盖正式版。
- 如果之前已经装过同包名、不同签名的包，系统会报
  `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，先卸载旧的那个再装即可。

### 7.2 常见构建错误

**① `No matching variant of com.android.tools.build:gradle:...`**
Gradle 跑在 JDK 8（或 11）上，而 AGP 需要 JDK 17+。`settings.gradle` 已经内置了自检，
会直接打印中文修复步骤。修复方式：

- Android Studio：`Settings → Build, Execution, Deployment → Build Tools → Gradle`
  → **Gradle JDK** 选 `jbr-17`（Studio 自带）或本地 JDK 17 → Sync。
- 命令行（Windows）：
  ```bat
  set JAVA_HOME=C:\Program Files\Android\Android Studio\jbr
  gradlew.bat clean assembleDebug
  ```
- 只对本次生效：`gradlew.bat -Dorg.gradle.java.home="C:\Program Files\Android\Android Studio\jbr" clean assembleDebug`
- 永久生效（本机配置，勿提交）：在 `%USERPROFILE%\.gradle\gradle.properties`
  加 `org.gradle.java.home=C:\\Program Files\\Android\\Android Studio\\jbr`

**② `Unsupported class file major version 6x`**
JDK 太新（Gradle 8.10 最高支持 JDK 23）。切回 JDK 17 或 21。

**③ `Failed to find target with hash string 'android-34'`**
SDK Platform 34 没装：`Tools → SDK Manager → Android 34`，勾选 *SDK Platform* 与
*Android SDK Build-Tools 34*。

**④ `Plugin [id: 'com.android.application'] was not found`**
第一次同步时网络没连上 `google()` / `mavenCentral()`；挂上代理后
`File → Invalidate Caches / Restart` 再同步。

**⑤ 打开工程时提示 AGP 版本不兼容**
说明 Android Studio 太旧（低于 Hedgehog）。升级 Studio，或改回 AGP 7.4.2 + Gradle 7.6.4 +
JDK 17 这一组合（JDK 依旧是 17，不要用 8/11）。

**⑥ `Ble_Activity.java:537: 需要常量表达式 / constant expression required`（`case R.id.xxx`）**
AGP 8 起 `android.nonFinalResIds` 默认为 `true`，`R` 里的资源 id **不再是编译期常量**，
所以 `switch (v.getId()) { case R.id.send_btn: ... }` 会报"需要常量表达式"。
本项目已把 `Ble_Activity#onClick` 改成等价的 `if / else if`；以后新增代码同理，
不要对 `R.id` 用 `switch`。若确实想保留 switch 写法，可在 `gradle.properties` 里加：

```properties
android.nonFinalResIds=false
```

（但 AGP 9 会移除该开关，建议直接用 if-else。）

**⑦ 提示 `Could not install Gradle distribution` / wrapper 版本过旧**
仓库里的 `gradle-wrapper.jar` 是 2019 年的老文件，正常情况下仍能下载 8.10.2；若报错，
重新生成 wrapper（会同时更新 jar）：

```bash
gradlew.bat wrapper --gradle-version 8.10.2 --distribution-type bin
```

或者用 Android Studio 打开工程后点 `Sync`，让它自动补齐 wrapper。

单元测试（`app/src/test/java/com/zxw/fitness/PoseAnalyzerTest.java`）用合成关键点验证：
标准俯卧撑计数、幅度不足/塌腰/跪姿的识别、站立不误计数、抖动过滤、倒立计时与倾斜拒绝、
骨架文件读写、历史记录 key 稳定性。`WallSitMultiGroupTest` 覆盖第二组短于第一组时累计持续增长、
宽限期与逐帧回放；`StreamCopyTest` 覆盖分块复制和写入/刷新错误。`SquatPanRecoveryTest` 覆盖连续横移、单侧和丢点、异常膝点、防误计、个人校准及骨架文件回放；`SquatPanRecorderTest` 覆盖记录器选择、成绩/校准持久化和回放；`VideoReanalysisRunnerTest` 用模拟帧源与检测器验证视频时间采样、当前滤波、校准边界、取消和资源释放。`VideoReanalysisIntegrationTest` 使用 Chromium 的短旋转 MP4 测试真实解码和 ML Kit 调用，样片不含运动人体；还需在设备上运行并用真实训练视频验证准确性、同步与旋转。Android 仪器测试还覆盖累计字段兼容与复制路径；模拟环境运行不能代替设备上的仪器测试。

### 7.3 真机回归清单（尚待执行）

1. 安装 debug 包（`com.zxw.dev`），第一组靠墙蹲坚持较长、站起超过宽限期后做较短的第二组；
   检查大号累计持续增长，休息时不增长，结束/历史分别显示累计与最长单组。
2. 播放新旧靠墙蹲记录：有骨架时检查累计随拖动重算，无骨架旧记录只显示最长；同时检查视频+骨架和纯骨架两种回放。
3. 在回放页导出到本机文件夹，等待完成后用文件管理器播放；确认原文件仍可回放，导出的文件不含骨架叠加。
4. 测试取消、没有视频、切换上一/下一条、选择器中系统重建页面、低空间/不可写目标，以及较大视频导出；
   错误后检查目标是否留下不完整文件。在 Android 版本及文件提供方不同的设备上分别验证。
5. 深蹲选择「逐帧重新找人」：人在画面内时下蹲、横移手机再站起，检查原始骨架能否重新伸直、顶部有无识别偏慢提示；随后做完整深蹲检查计数，验证已有成绩和个人目标不被清除。再退出重选「连续跟踪」对照流畅度和横移恢复，不预设某种模式一定更准。
6. 在上述两种深蹲模式分别确认录像是否成功，打开带视频记录等待自动识别；对比「新原始」「新滤波」「录制」中横移/站起的骨架，拖动、暂停和倍速时检查视频与点的对齐。取消、重试、切换上下条、退出页面、无视频/无骨架和失败回退都要检查；新识别不能更改历史成绩、个人目标和原 MP4。比较前后摄、旋转、动作快慢、多人入画、光线及设备性能。
7. 在设备上运行 `:app:connectedDebugAndroidTest` 中的 `VideoReanalysisIntegrationTest`，检查旋转视频抽帧与真实 ML Kit 调用；再用真实训练视频观察骨架，因为测试样片不含运动人体。

## 8. 已知限制

> 这些限制的解决计划见 [ROADMAP.md](../ROADMAP.md)（v1.2 ~ v1.4 里程碑）。


1. **靠墙倒立**的"贴墙"是脚踝代表点横向稳定的启发式代理，不是真的检测墙面或接触；
   建议手机侧向放置，让人与墙面都在画面里。
2. 旧录制骨架与视频的起点不同；新识别按视频时间近似抽帧，但解码帧与请求时刻、播放器 seek 仍可能有偏差。前摄镜像、录像旋转/显示与横滚方向尚未真机验证。
3. 机位效果需实测，不能断言侧面总是最准。俯卧撑深度使用肘角和手腕相对高度两路较大值，视角代理还影响侧面髋角检查；引体向上需要手臂关键点。
4. 只有部分设备支持"预览 + 分析 + 录像"三路同时运行；不支持时会自动降级为
   "预览 + 分析"，此时只保存骨架回放（历史记录里不会显示「视频」标记）。
5. 录像原件保存在 App 私有目录，可通过回放页导出原 MP4 到用户选择的位置，但不含骨架叠加；
   不保证自动显示在相册中。仅骨架记录没有可导出的视频。
6. 光照不足、深色衣服、背景杂乱会降低关键点置信度，界面会提示"未检测到人体/手臂完整入镜"。
7. **跑步计步**根据左右脚踝高度交替估计步数，不检测真实离地、不测距离与配速；需要双脚踝始终入镜，过快或噪声也可能造成漏计/误计。
8. **靠墙蹲**靠膝角 + 髋膝高度差近似判断坐姿，膝角 <60° 不算；不检测墙面或贴墙接触。
9. 诊断不提供多人身份跟踪；人体切换或被遮挡时，即使重捕获成功也不能保证仍是同一人。
10. 算法验证主要来自合成轨迹。本轮离线运行了纯 Java 的 JUnit 测试并对部分代码做 Android API 34 存根编译；
    尚未完成完整 Gradle/Android 构建、设备测试或真实视频准确率验证。
